# WePush Next 0.1.0-alpha.4 — Public Preview

`0.1.0-alpha.4` 把 Next 从“只有通用 HTTP”推进到可使用真实渠道的自部署消息系统。用户在自己的 Service、Agent 或 Embedded Java 应用中，使用自己的 SMTP、企业 IM、阿里云和微信账号完成配置与发送；WePush 不提供公共 SaaS、账号注册、计费订阅、平台代理或云 KMS。

## 本版新增渠道

| Provider ID | 能力 |
|---|---|
| `wepush.email.smtp` | NONE/STARTTLS/TLS、可选认证、文本/HTML Multipart、Reply-To、CC/BCC |
| `wepush.bot.feishu` | Text/Post/Interactive/Raw、自定义机器人签名、关键词与双窗口安全限流 |
| `wepush.bot.dingtalk` | Text/Markdown/Link/Action Card/Raw、时间戳 HMAC 签名与安全限流 |
| `wepush.bot.wecom` | Text/Markdown/Raw、官方 Webhook 校验与安全限流 |
| `wepush.sms.aliyun` | `SendSms`、POP HMAC-SHA1 签名、模板变量、`OutId` 追踪与业务错误映射 |
| `wepush.wechat.official` | 模板、订阅、客服消息；Access Token 缓存和安全刷新 |
| `wepush.wechat.mini` | 订阅、统一服务消息；Access Token 缓存和安全刷新 |
| `wepush.wecom.app` | 企业微信任意应用消息 Payload、用户/部门/标签目标和重复检查 |

原有 `wepush.http` 继续内置，因此 Service 和 Agent 共发现 9 个内置 Provider。每个新 Provider 的实现版本为 `0.1.0`，与产品版本独立。

## 统一交付边界

- 每个渠道都有 Account、Message、Recipient Schema，WebUI 从实时 Schema 渲染表单和默认消息示例。
- 密码、Webhook、签名 Secret、AccessKey Secret、AppSecret 和 CorpSecret 只以 SecretRef 出现在配置中。
- Dry Run 完成配置、Recipient、模板和 Payload 校验，但不解析 Secret、不获取 Token、不访问网络。
- 本地 mock 测试覆盖实际 SMTP/HTTP 协议、厂商签名、Token 刷新、响应上限和错误分类；Engine 纵向测试逐一执行 8 个标准渠道。
- Service 与 Agent 通过 ServiceLoader 自动装载；Embedded Java SDK 仍要求调用方显式选择 Factory。
- 机器人、短信和微信系生产实现固定或严格校验厂商官方端点，防止把 Secret 与消息发送到任意主机。

完整最小配置、Recipient 字段和 Provider Code 处理见[《内置 Provider 指南》](../provider-guide.md)。

## 发送语义

外部消息渠道通常不提供 Exactly Once。本版本明确区分：

- 连接建立前的确定失败可以按策略重试；
- 厂商显式频控返回 `RATE_LIMITED`，可携带建议等待时间；
- 提交后超时、I/O 或 `5xx` 返回 `UNKNOWN`，默认不自动重发；
- 阿里云 `OutId` 只用于追踪，不代表服务端去重；
- 企业微信应用消息默认使用厂商提供的短窗口重复检查。

## WebUI 与 SDK

- Schema Renderer 新增本地 `$ref` 解析和嵌套 SecretRef 默认对象，渠道配置不再需要手写完整引用骨架。
- 标准渠道消息 Schema 带可编辑示例；正式值仍需替换为用户自己的模板、签名和账号参数。
- 主发行包和独立 Java SDK 附件加入 `provider-standard` POM/JAR；SMTP 的 Angus Mail 依赖由 Maven 根据 POM 解析。
- OpenAPI 与 Remote SDK 的 Provider Catalog/Schema 通用契约保持不变，客户端无需针对每个渠道增加硬编码 API。

## 预览限制

- 本版本不会替用户验证第三方账号额度、模板审核状态、手机号/关注/订阅授权或厂商侧配额；首次正式发送必须使用自有测试目标小范围验证。
- API、Schema、Provider 行为和升级路径在预览期仍可能不兼容变化。
- Desktop 和安装包未使用商业代码签名或 Apple Notarization，请只从项目 Release 下载并校验 SHA-256。
- 本版本不建设公共 SaaS、自助注册、计费订阅、公共租户平台、云 KMS/Secret Manager 或托管更新服务。
